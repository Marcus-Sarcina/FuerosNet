RESOLVED (design 16.4, 2026-09-04): when shared capacity cannot satisfy every eligible
principal, the max-flow VALUE is unique (individual standing and the aggregate bound are
well-defined) but the ALLOCATION is not.  The reference metric ranks in three passes:
AVAILABLE FLOW FIRST -- it is what the metric measures -- then the SHORTER PATH among
candidates the flow ranks equally, because a longer path is less trustworthy by nature,
then consideration order for TRUE TIES only.  All three are REFERENCE POLICY, not a network
invariant: per-observer trust (16.1) means no party consumes another's computation, so a
policy allocating differently still conforms.  Note for implementers (tested above): one
multi-sink max-flow delivers the PATH-LENGTH pass for free, misses the TIE pass silently
(at equal path length it follows the graph's construction order, not the candidate order),
and cannot deliver the FLOW pass at all.  Rank explicitly.
